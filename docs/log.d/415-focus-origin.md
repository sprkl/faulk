* **Fix** (#415): intermittent e2e flake on a busy CI shard — after closing a device knob's context menu by clicking an item, Space incorrectly toggled the transport. Root cause: `Slider.closeMenu()` calls `root.focus()` with `lastInput === 'pointer'`; if the element is already focused (typical after a right-click), a second `focus()` call is a no-op (no `focusin` fires), leaving `pointerFocused` stale. Then a subsequent key press on the focused slider failed to reassert keyboard origin, and Space erroneously toggled the transport. Fix (option A — lead decision): focus origin follows the **last input modality**; a non-musical UI-shortcut key (`Delete`, arrows, `Backspace`, `Home`/`End`, etc.) on an already-focused slider clears `pointerFocused`, reasserting keyboard origin even without a `focusin`. Musical keys (`KeyA`…`KeyP`, `Semicolon`, octave steps `Z`/`X`) are excluded: pressing a note on a mouse-used knob must not prevent the note from sounding. The reassertion is scoped to `role="slider"` controls: other controls (buttons, links) are left unchanged so that Escape on a menu trigger does not accidentally switch them to keyboard origin. Consequence (option A): after a non-musical key on a mouse-focused slider, letters no longer play a note on that slider until the next pointer press restores pointer origin. Test: `keyboard.test.ts` covers both `spaceTogglesTransport` and `playsNote` for the full state-machine (`pointer → UI key → keyboard → pointer` cycle, playing keys excluded, sliders only); `continuous.spec.ts` verifies the behavior change end-to-end (mouse click → Delete → no voice → click → voice) and the regression sequence (right-click menu → close → Backspace → Space does not toggle).
