* **Fix** (#394): automation follow-ups from #388. A lane cleared (`automation.lane.clear`) or deleted gives its parameter back to the stored project value in the engine: a device parameter through a `ParamSet` from the compiler (the lane target is cached in `EngineSlots::lane_targets`, the descriptor default stands in for a key the project does not hold), a mixer field through the engine (`RtMsg::LanePut` with no point forgets the lane like a remove). A stop, a seek or a pause that cues the playhead where it already stands now releases the page's held gestures, as the engine does (`ProjectStore.cued`). The survival rule of a held gesture at a snapshot relay or a track restart is written in the AM-2 spec; the unchanged-gesture hold (point 2) moved to #417 because it needs the gesture's intent in the engine messages. Tests: emptied lane in the engine, `restore` of device parameters in the compiler, the nine arrangement commands never touch a lane, the pan mark, the cue release. AM-1 spec lists `arrangement.place_from_slot`, `arrangement.place_scene` and `arrangement.restore` among the commands that never touch lanes.
