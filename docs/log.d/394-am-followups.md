* **Fix** (#394): automation follow-ups from #388. A lane with no point does nothing, so the compiler no longer uploads it: a lane cleared (`automation.lane.clear`) leaves the engine like a deleted one, and a device parameter it drove gets the stored project value back through a `ParamSet` (descriptor default for a key the project does not hold; none while another lane still drives the parameter); a mixer field goes back to its fader through the existing remove. The lane target is cached in `EngineSlots::lane_targets`. A stop, a seek or a pause that cues the playhead where it already stands now releases the page's held gestures, as the engine does (`ProjectStore.cued`, from the page effects table). The survival rule of a held gesture at a snapshot relay or a track restart is written in the AM-2 spec; the unchanged-gesture hold (point 2) moved to #417 because it needs the gesture's intent in the engine messages. Tests: restore messages in the compiler, a rendered cleared and undone cutoff lane, the nine arrangement commands never touch a lane, the pan mark, the lane drawn before its first point, the cue release through the effects table. The helper embeds the compiler: a helper published before this change keeps the last lane value on a cleared device lane in Boost mode (no version bump, reported to the founder). AM-1 spec lists `arrangement.place_from_slot`, `arrangement.place_scene` and `arrangement.restore` among the commands that never touch lanes.
